# 02.1: the site as a Cloudflare Worker, and no GitHub links

Fixes after Marc's test of phase 02, on 13 November 2026.

## Why

- **Cloudflare:** Marc made the site a **Worker** with static assets, not a Pages project. The dashboard now offers Workers first: "i couldn't find just pages.. only workers and pages..". The Worker is right, and it's what Cloudflare recommends now. It serves `cfgaming.app` as its custom domain, and its `workers.dev` address is "Previews Only".
  - The site was written for Pages, so the repository has no `wrangler.jsonc` for the Worker. Cloudflare's docs say a build without one "will trigger automatic project configuration", which opens a pull request. None was opened.
  - Seen live on 13 November:
    - an address the site doesn't have answers 404 with an empty page, instead of the site's own `404.html` (the default `not_found_handling` is `"none"`);
    - the only build from GitHub is the first, five hours old, so phase 02's push isn't live;
    - phase 02's `pages.dev` rule in `_headers` matches nothing on a Worker.
- **GitHub links** (Marc: "i don't want links to the github yet as when i ask for payment they will circumvent it to download from guithub"). His answers:
  - **Licences' source links** (Wine's changes, CF Gaming's build of Mupen64Plus-Next): "Keep, until 27g". Their licences need that source available.
  - **Privacy's Questions section,** which linked GitHub's issues: "Remove it for now".
  - **Known issues** on Before you start, which linked the release notes on GitHub: "Show the notes on the site".

## The steps

1. **`wrangler.jsonc`**, from Cloudflare's Astro guide and the Wrangler settings (read 13 November):
   - the name `cfgaming-site`, which must match the Worker's in the dashboard;
   - today's compatibility date;
   - the assets in `./dist`, with `not_found_handling` `"404-page"` and `html_handling` `"auto-trailing-slash"`;
   - `workers_dev` and `preview_urls` both `false`, so `cfgaming.app` is the only address.
2. **`_headers`:** the `pages.dev` rules taken out.
3. **GitHub links out:**
   - the footer's "On GitHub", and the site's own source on Licences;
   - Privacy's Questions section, and the links in `src/lib/site.ts` nothing uses any more.
   - Kept:
     - the download itself, until 27d or 27g;
     - Licences' links to the source Wine's and Mupen64Plus-Next's licences require, and the credits to other people's projects;
     - Privacy's plain words that the download and updates come from GitHub, which keep it true.
4. **Known issues on the site:**
   - the latest release's "Known issues", read with the download as the site is built, and shown on Before you start through Astro's own Markdown (a content loader's `renderMarkdown`, so no dependency is added);
   - Licences' "CF Gaming 11.5's" link to the release page becomes plain words.
   - The build stops if the notes have no Known issues, or if they have something the site can't show safely: HTML, or a code block, whose colours would need inline styles that the Content-Security-Policy refuses.
5. **The docs:** `CLAUDE.md`, the reviewer and phase 06 say Worker, not Pages. Phase 06's deploy hook needs checking again: Cloudflare's Workers Builds docs, read 13 November, don't mention deploy hooks.

- **The Worker has its own settings, in `wrangler.jsonc`.** At the next build, Cloudflare stops guessing:
  - an address the site doesn't have will show the site's own not-found page, with a 404;
  - `/about` goes to `/about/`;
  - `cfgaming.app` is the only address, with no `workers.dev` and no previews.
- **No links to CF Gaming's GitHub pages:**
  - the footer's "On GitHub" is gone, and so is Licences' link to this website's source;
  - Licences names "CF Gaming 11.5's" changes in plain words;
  - Privacy's Questions section is gone.
  - What's left: the download button (a GitHub file), the 13 Wine patches and Mupen64Plus-Next's source, which Marc kept until 27g. Credits to other people's projects stay too.
- **Known issues on Before you start:** "Known issues" (which was "What it doesn't do yet"), with the latest release's list from its notes, folded away under "CF Gaming 11.5's known issues". All 45 entries of 11.5 are there.
- **The build stops** if the notes have no Known issues section, or if that section is empty, or has HTML, a code block, a picture, or anything linking to `dusky101`.

### What's inferred
- **Two GitHub requests per build:** Astro probably reads content in a separate step from building the pages, so the release is likely fetched twice. That's well inside GitHub's 60 an hour, and a `GITHUB_TOKEN` in the build's settings lifts the limit.
- **Why phase 02's push didn't go live:** without a `wrangler.jsonc`, Cloudflare's docs say each build sets the project up itself and opens a pull request, and none was opened. No build log was seen.
