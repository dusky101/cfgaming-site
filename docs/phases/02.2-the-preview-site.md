## The aim

Changes show first on a preview of their own on Cloudflare, and reach `cfgaming.app` only when Marc says the preview is right.
- **`preview`** is the branch the work happens on. Cloudflare builds it as a Preview.
- **`main`** is the live site, and stays as it is until then.

## What it starts from

- **Hosting:** the site is the `cfgaming-site` Worker, built by Workers Builds at each push to `main` (phase 02.1).
- **Version addresses:** `wrangler.jsonc` sets `preview_urls` to `false`, which turns them off. That's why `https://3b627764-cfgaming-site.marc-oliff.workers.dev` showed "There is nothing here yet".
- **Cloudflare's docs (read 14 November), proved:**
  - builds for other branches are switched on at Settings › Build › Branch control › **Enable Preview Builds**;
  - their command, `npx wrangler preview`, makes a Preview that "always serves the latest deployment" at `<preview-name>-cfgaming-site.<subdomain>.workers.dev`, with `X-Robots-Tag: noindex`;
  - Previews are public unless Cloudflare Access is put in front of them;
  - Workers connected before Previews existed may offer a one-time switch to them, which "cannot be reversed".
- **The docs don't say:**
  - whether a Preview's name is the branch's name;
  - whether `preview_urls: false` affects Previews;
  - whether a Worker with static assets only gets them;
  - what Access costs.
- **Set up before the restart, on this Mac only:**
  - `.claude/rules/cloudflare.md`, with the two branches and what may be changed in Cloudflare;
  - `CLAUDE.md`;
  - `.claude/hooks/guard_bash.py`: no commits on `main`, and nothing merged into it but `git merge --ff-only preview`;
  - `.claude/hooks/guard_cloudflare.py`: the irreversible Cloudflare calls refused;
  - `settings.json`: every Cloudflare plugin call asks Marc;
  - the two skills.
  - Work is now on the `preview` branch.

## Found through the plugin (14 November, reading only)

- **Signing in:** Marc signed in with "Read only" plus `workers-ci.write`. Those names come from the source of Cloudflare's MCP server; the docs don't list them. The consent screen showed read permissions and Workers CI Write. The ask rule prompted on the first call (`whoami`).
- **Preview builds were already on.** The Worker's build settings read `previews_enabled: true`, with preview builds running `npm run build` then `npx wrangler preview`. As a new Worker, it already uses Worker Previews, so no one-time switch is needed. **Nothing has been changed in Cloudflare.** There's no preview yet, because only `main` has ever been pushed.
- **Builds so far:** the first one, `manual`, on 13 November at 17:36, and `d45896d`, a `push_event` at 23:51. Both succeeded.
- **The Worker's own `workers.dev` address** is off (`enabled: false`). Version addresses are off too (`previews_enabled: false`, from `preview_urls: false` in `wrangler.jsonc`).
- **Cloudflare's docs, read through the plugin:**
  - a Preview's name "defaults to your current Git branch", so this one's address should be `preview-cfgaming-site.<subdomain>.workers.dev` (Cloudflare's pattern; the exact address isn't proved yet);
  - "Cloudflare adds this header automatically to `workers.dev` Preview URLs": that's `X-Robots-Tag: noindex`;
  - a Preview needs a place to be served from: `workers.dev` Preview URLs, or a custom domain set up for previews. Without one, the build reports "No Preview URL".
  - **Not settled:** whether `preview_urls: false` turns off Worker Previews' `workers.dev` addresses as well as version addresses. The docs set `preview_urls` "then run `npx wrangler deploy`", which would mean `main`. The first preview build will show it.
- **Deploy hooks exist for Workers Builds:** "Create a deploy hook", `POST /accounts/{account_id}/builds/workers/{script_name}/deploy_hooks`, needs Workers CI Write. That's for phase 06.
